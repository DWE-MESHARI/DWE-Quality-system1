# نظام إدارة جودة خدمة العملاء — دار وإعمار (نسخة Supabase)

## هيكل المشروع
```
index.html            الصفحة الرئيسية + شاشة الدخول
assets/logo.png        شعار دار وإعمار
css/style.css          التصميم الأساسي
css/clay.css           ثيم Clay بالهوية البرتقالية والبيضاء
js/app.js              منطق النظام كاملًا (لم يتغير إلا سطر الاستيراد أعلاه)
js/supabase.js          الربط مع Supabase (بديل js/firebase.js، بنفس الواجهة تمامًا)
js/supabase-config.js   رابط ومفتاح مشروع Supabase
js/firebase.js / js/config.js   النسخة القديمة على Firebase، أُبقيت كمرجع واحتياط فقط ولا تُستخدم الآن
firestore.rules        قواعد أمان Firebase القديمة (للأرشيف فقط، غير مستخدمة مع Supabase)
supabase_setup.sql     سكربت إنشاء الجداول والحماية في Supabase (نفّذتِه مسبقًا في مشروعك)
```

## ما تغيّر في هذا التحديث
- **الهوية البصرية:** الألوان الأساسية صارت برتقاليًا فاتحًا وأبيض (الشريط الجانبي، الأزرار، شاشة الدخول)، وبقيت ألوان الأقسام والموظفات ومستويات التقييم كما هي لتمييزها.
- **الشعار:** أُضيف شعار دار وإعمار بجانب اسم "نظام الجودة" في الشريط الجانبي، وفي أعلى شاشة الدخول، وكأيقونة للمتصفح.
- **قاعدة البيانات:** انتقل النظام بالكامل من Firebase إلى **Supabase** (نفس المشروع الذي أنشأتِه أثناء التجربة: `DWE-QualitySystem`).

## الربط بـ Supabase
`js/supabase-config.js` معبّأ مسبقًا برابط ومفتاح مشروعك:
- Project URL: `https://cjyuphlhhrizglqhfxvg.supabase.co`
- المفتاح: anon/publishable (عام وآمن للمشاركة بطبيعته؛ الحماية الفعلية هي RLS في قاعدة البيانات، وليس إخفاء هذا المفتاح)

الجداول (`emp`, `ev`, `rep`, `log`, `cfg`, `roles`) والحماية (RLS) جاهزة بالفعل من `supabase_setup.sql` الذي نفّذتِه سابقًا في SQL Editor.

## قبل الاستخدام الفعلي — تنظيف بيانات التجربة
أثناء التعلم أضفنا بيانات تجريبية (موظفة "Muneera"، وربما "مقاري"، وتقييمات وسجلات اختبار). امسحيها من مشروعك الحقيقي قبل البدء الفعلي، من **SQL Editor**:
```sql
truncate table ev, rep, log restart identity;
delete from emp;
alter sequence emp_id_seq restart with 1;
```
هذا يُفرغ كل شيء عدا `roles` و`cfg` (يبقى حسابك admin وإعداداتك كما هي).

## نقل بياناتك من النظام القديم (Firebase)
1. في النظام القديم: **الإعدادات ← تصدير نسخة احتياطية Excel**.
2. في هذا النظام: **الإعدادات ← استيراد**، واختاري نفس الملف. يضيف الموظفات والتقييمات تلقائيًا في Supabase.

## التشغيل والنشر
- محليًا: لا يعمل بفتح الملف مباشرة (وحدات ES)؛ شغّلي `python3 -m http.server` ثم افتحي `http://localhost:8000`.
- على GitHub Pages / Vercel: ارفعي محتوى هذا المجلد كاملًا (بما فيه `assets/`) مع الحفاظ على هيكل المجلدات، ثم فعّلي الاستضافة كالمعتاد.

## العودة إلى Firebase عند الحاجة
إن أردتِ التراجع مؤقتًا، غيّري سطر الاستيراد الأول في `js/app.js` من:
```js
import {DB,onAuth,login,logout,getRole} from './supabase.js';
```
إلى:
```js
import {DB,onAuth,login,logout,getRole} from './firebase.js';
```
ولا حاجة لأي تعديل آخر، لأن الملفين يوفّران نفس الواجهة بالضبط.

## أمان
- **لا** تفتحي RLS بقاعدة "allow all" مطلقًا.
- سجل التغييرات (`log`) للإضافة فقط ولا يمكن تعديله أو حذفه من أحد، حتى المدير، بتصميم مقصود.
- مفتاح `service_role` في Supabase لا يجب أن يظهر في أي ملف من هذا المشروع أبدًا؛ المستخدم هنا هو anon/publishable فقط.
