# صفحة تجريبية — Supabase

صفحة واحدة (`index.html`) للتعلم فقط، منفصلة تمامًا عن نظام الجودة الفعلي (Firebase). تتصل بمشروعك في Supabase وتقرأ/تكتب في جدولي `emp` و`ev` الحقيقيين.

## التشغيل
لا تحتاج خادمًا محليًا ولا وحدات ES؛ يكفي فتح `index.html` مباشرة، أو رفعه على GitHub Pages:
1. ارفعي محتوى هذا المجلد إلى مستودع.
2. من إعدادات المستودع: **Settings ← Pages ← Branch: main / root**.
3. افتحي الرابط الذي يعطيك إياه GitHub.

## تسجيل الدخول
استخدمي بريد وكلمة مرور مستخدم حقيقي من مشروعك: **Authentication ← Users**.

إذا ظهر "غير مسجّل دخول" تحققي من:
- **كلمة المرور**: إن أُنشئ المستخدم يدويًا وواجهتِ رفضًا، يمكن تعيين كلمة مرور جديدة من **SQL Editor**:
  ```sql
  update auth.users
  set encrypted_password = crypt('كلمة_المرور_الجديدة', gen_salt('bf'))
  where email = 'البريد@مثال.com';
  ```
- **تأكيد البريد**: بعض الحسابات المُنشأة يدويًا تبقى غير مؤكَّدة، ويمكن تأكيدها بـ:
  ```sql
  update auth.users
  set email_confirmed_at = now()
  where email = 'البريد@مثال.com';
  ```
- بعد أي استعلام من الاثنين تأكدي من ظهور "Success" في SQL Editor قبل إعادة المحاولة.

## أين الأخطاء الحقيقية؟
أسفل الصفحة مربع أسود بعنوان "سجل ما يحدث (تشخيصي)"، وهو يعرض رسالة Supabase الحرفية عند فشل أي عملية (دخول، إضافة، حذف...). هذا أول مكان يُرجع إليه عند أي مشكلة.

## الأمان
مفتاح `KEY` داخل `index.html` هو **anon / publishable key**، وهو عام وآمن للمشاركة بطبيعته (نفس فكرة `apiKey` في Firebase). الحماية الفعلية هي **Row Level Security (RLS)** المفعّلة على الجداول في Supabase، وليست إخفاء هذا المفتاح.
